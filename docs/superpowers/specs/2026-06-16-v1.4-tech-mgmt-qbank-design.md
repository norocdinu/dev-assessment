# v1.4 — Technology Management & Question-Bank Controls

**Date:** 2026-06-16
**Status:** Approved (brainstorming → ready for implementation plan)
**Scope:** Three related features in the admin question-bank / technology area. No candidate-facing changes.

## Goal

Give owners the ability to manage the technology list (add, delete, restore) directly, and improve question-bank usability with a page-size control and a scoped CSV export. Today there is no way to add or remove a technology beyond the three seeded rows, the bank always shows 25 rows per page, and export dumps everything matching the active filters with no scope choice.

## Constraints & current state

- `technologies` is `(id, slug, name, created_at)` with only a `GET /technologies` route. No add/delete API exists.
- `questions.technology_id` **and** `test_configs.technology_id` are both `NOT NULL REFERENCES technologies(id)` with **no `ON DELETE` rule** → Postgres blocks deleting any technology that still has questions or configs, even archived ones.
- Questions already have a two-tier removal model: **archive** (`is_active=false`, reversible) and **hard delete** (blocked when the question is referenced by `candidate_answers`, i.e. used in a past submission).
- A "live link" = `test_links` row in state `created` or `active` (not yet `submitted`/`expired`).
- The question bank hardcodes `PAGE_SIZE = 25`; `listQuerySchema` already accepts `pageSize` up to 100. Selection state (`selectedIds` of `family_id`) already exists on the page.
- All question mutations are `requireRole('owner')`. Export is already owner-only.
- Audit gap: technologies and test-configs are not currently audited (per backend-restructure roadmap). This work closes the technology side.

## Feature 1 — Technology management (inline on Question Bank)

### UI
A **"Manage technologies"** button in the question-bank filter bar (owner-only) opens a modal:
- List of technologies → **name, slug, live question count**. Active techs shown by default; a "Show archived" toggle reveals archived techs.
- **Add technology** form: `name` + `slug`. Slug auto-derived from name (lowercased, non-alphanumerics → hyphens, trimmed), editable, must be unique. 409 on duplicate slug.
- Per-row **Delete** (active techs) and **Restore** (archived techs).

### Delete flow
Frontend calls a usage precheck, then shows the appropriate dialog:
- **Empty tech** (0 questions, 0 configs) → simple confirm → hard-delete the row.
- **Has questions** → choice dialog with two options:
  - **Archive** — `technologies.is_active=false` and archive all its questions (`is_active=false`). Reversible, keeps all history.
  - **Delete permanently** — delete the tech + its questions; any question referenced by `candidate_answers` is **archived instead** of deleted, and that count is reported back to the user.
- **Test-configs guard** (both choices): configs with **no live links** are archived (`is_active=false`); if **any** config has a live link (`created`/`active`), the entire operation is **blocked** (409) with the blocking config name(s). Nothing is mutated when blocked.

All delete/archive/permanent paths run in a single transaction.

### Restore
**Restore** sets `technologies.is_active=true` (un-hides the tech). Its questions remain archived — the user re-activates them via the existing question "Show archived" controls. (Restore does not auto-reactivate questions, to avoid resurrecting questions the user had separately archived.)

### Schema
Migration `0004_technology_lifecycle.sql`:
```sql
ALTER TABLE technologies ADD COLUMN is_active BOOLEAN NOT NULL DEFAULT TRUE;
```
All technology dropdowns and the question-list `JOIN technologies` filter to `t.is_active = TRUE` (the manage modal can request archived too).

### API (all owner-only, audited)
- `POST /technologies` `{ name, slug }` → `201` tech / `409 { error: 'duplicate_slug' }`.
- `GET /technologies` → active only by default; `?include_archived=true` returns all (for the modal). Each row carries a `question_count` (latest, active+archived) and `is_active`.
- `GET /technologies/:id/usage` → `{ questionCount, activeQuestionCount, configCount, liveLinkCount, blockingConfigs: [{id, name}] }`.
- `DELETE /technologies/:id?mode=archive|delete` → guarded transaction. Success: `{ archivedQuestions, deletedQuestions, archivedConfigs }`. Blocked: `409 { error: 'live_links', blockingConfigs }`.
- `POST /technologies/:id/restore` → `{ ok: true }` (sets `is_active=true`).

Audit actions: `technology.create`, `technology.archive`, `technology.delete`, `technology.restore` (entity_type `technology`).

## Feature 2 — Page-size control

Dropdown next to the question-bank table: **10 / 25 / 50 / 100 / All**, default **25**.
- Selecting a value sets `pageSize` and resets to page 1.
- **All** sends `pageSize=all`; `listQuerySchema` is extended to accept the literal `all` (coerced numbers as today, plus `'all'`). When `all`, the list query runs with **no `LIMIT`/`OFFSET`** and returns every matching row; `page` is forced to 1.

---

## Feature 3 — Export scope modal

"Export CSV" opens a modal with three radio choices:
- **Selected** — only checked rows. Enabled only when ≥1 row is selected; becomes the **default** in that case.
- **Current page** — the rows currently shown (current `page` + `pageSize`).
- **All filtered** — everything matching active filters (today's behavior). Default when nothing is selected.

`GET /questions/export` gains optional params:
- `ids` — comma-separated `family_id`s → exports those families' `is_latest` rows ("selected"). When present, filters are ignored.
- `page` + `pageSize` → exports that page ("current page"), applying the same filters and `ORDER BY created_at DESC` as the list so output matches the screen.
- Neither → exports all filtered rows (current behavior).

CSV columns and escaping are unchanged.

## Testing

- **API unit/integration:** slug derivation + uniqueness (409); usage precheck counts; delete `mode=archive` archives tech+questions and active-link-free configs; `mode=delete` hard-deletes deletable questions and archives submission-referenced ones; live-link guard blocks (409) and mutates nothing; restore flips `is_active`; export `ids` / `page` / all-filtered each return the expected row set; `pageSize=all` returns all rows with no limit.
- **Manual (web):** add a tech, filter by it; delete empty vs populated tech (both choices); blocked-by-live-link path; restore; page-size dropdown incl. All; export each scope and diff the CSVs.

## Out of scope

- Renaming/editing an existing technology's name or slug (add only, for now).
- Reassigning questions between technologies.
- Auto-reactivating questions on tech restore.
- Lifting the export to a background job (synchronous is fine at current data sizes).
